# 15 · Журнал архитектурных решений (ADR)

Состояние каждого решения трактуется как исторически выбранный вариант, а не как утверждение о полной runtime-проверке. [ПРОВЕРЕНО: статус архивных решений]

## ADR-001 · TSDF + GPU Surface Nets как основной метод реконструкции

- **Контекст:** автономный шлем должен постепенно восстанавливать геометрию помещения по depth observations. [ПРОВЕРЕНО: границы проекта]
- **Варианты:** TSDF + Surface Nets; разреженное облако без связной поверхности; офлайн-реконструкция на ПК; Gaussian Splatting. [ПРОВЕРЕНО: перечисленные альтернативы]
- **Решение:** использовать встроенный в SDK конвейер TSDF + GPU Surface Nets; живые точки показывать как индикацию процесса. [ПРОВЕРЕНО: pinned dependency/source]
- **Обоснование:** повторно используется готовый цикл SDK и compute pipeline; отдельный full reconstruction engine не требуется. [ПРЕДПОЛОЖЕНИЕ: rationale]
- **Последствия:** критичны бюджет GPU-памяти и корректность readback; дефекты меша и тепловой бюджет требуют проверки на шлеме. [ПРОВЕРЕНО/ТРЕБУЕТ ПРОВЕРКИ]
- **Отклонённые альтернативы:** Gaussian Splatting отложен, так как обучение/rendering в текущей цели не подтверждены; одно облако точек не даёт связной поверхности. [ПРОВЕРЕНО: решение проекта; [ПРЕДПОЛОЖЕНИЕ] сравнительная оценка]

## ADR-002 · Фиксировать RoomScan по Git revision

- **Контекст:** кэш SDK и расположение патч-мостов должны воспроизводиться. [ПРОВЕРЕНО]
- **Варианты:** плавающая ветка, floating latest, immutable commit SHA. [ПРЕДПОЛОЖЕНИЕ: список вариантов]
- **Решение:** revision `4791b24b81015641d4cfb010a93c6283d4eb3dee`. [ПРОВЕРЕНО: `Packages/manifest.json`]
- **Обоснование:** мосты Arescope доступны только внутри сборки SDK и используют внутренние типы; плавающий revision может менять API. [ПРОВЕРЕНО: pin/patch workflow]
- **Последствия:** обновление SDK требует аудита, повторного применения patch scripts, сборки и полного QA. [ПРОВЕРЕНО: build procedure]

## ADR-003 · Ограниченный GPU readback вместо чтения полного буфера

- **Контекст:** GPU-буферы могут быть существенно больше активных данных; прежний full-buffer readback на устройстве возвращал пустой результат. [ПРОВЕРЕНО: история исходника и headset log]
- **Варианты:** полный async readback; readback диапазона по active counters; полный synchronous read; использовать только CPU refined mesh SDK. [ПРОВЕРЕНО: рассматривавшиеся подходы]
- **Решение:** сначала читать counters, ограничивать счётчики ёмкостью буферов, читать используемые диапазоны; при async-ошибке пробовать synchronous fallback и SDK refined mesh. [ПРОВЕРЕНО: source версии 0.5.7+]
- **Обоснование:** ограничить объём передачи и получить меш до освобождения ресурсов остановленного scanner. [ПРОВЕРЕНО: порядок операций]
- **Последствия:** согласованность counters/индексов остаётся условием корректности; rejected triangles нужно логировать. [ПРОВЕРЕНО]

## ADR-004 · Фильтр треугольников с порогом по медиане ребра

- **Контекст:** на снимках и логе были длинные линии через пустые области; старый фиксированный порог пропускал средние перемычки. [ПРОВЕРЕНО: screenshots/device log]
- **Варианты:** фиксированный мировой порог; адаптивный порог по медиане меша; фильтры компонент связности/нормалей; отключить mesh и показывать только точки. [ПРЕДПОЛОЖЕНИЕ: альтернативы]
- **Решение:** лимит ребра `clamp(medianEdge*4,0.06 m,0.30 m)`; треугольник отклоняется, если любое ребро превышает лимит. [ПРОВЕРЕНО: current source]
- **Обоснование:** локальный масштаб адаптируется к плотности, верхний предел ограничивает чрезмерно длинные рёбра. [ПРЕДПОЛОЖЕНИЕ]
- **Последствия:** загрязнение медианы и легитимные длинные поверхности создают false positives/negatives; нужны опорные комнаты и разбор логов. [ПРОВЕРЕНО: algorithmic risk]

## ADR-005 · Накопление живого облака в voxel cache

- **Контекст:** облако, полностью заменяемое при каждом read, выглядело разреженным и неравномерным во времени. [ПРОВЕРЕНО: отзыв пользователя]
- **Варианты:** заменять облако на каждом read; сохранять все вершины; deduplicate в voxels с пределом; показывать SDK mesh напрямую. [ПРОВЕРЕНО: перечисленные подходы]
- **Решение:** сохранять первое наблюдение в voxel размером 0.035 m, максимум 60,000 entries; период чтения 0.2 s. [ПРОВЕРЕНО: `LiveScanPoints.cs`]
- **Обоснование:** подавлять повторы близких точек, добавляя новые занятые ячейки. [ПРЕДПОЛОЖЕНИЕ]
- **Последствия:** кэш может достичь лимита и не обновляет ранее сохранённый цвет/позицию; выборка остаётся потенциально неравномерной. [ПРОВЕРЕНО: source behavior]

## ADR-006 · Мини-карта на высоте глаз, а не в плоскости взгляда

- **Контекст:** требование: при взгляде на пол пол не должен попадать на карту; дверь на высоте глаз должна отображаться; полоса следует за текущей высотой головы. [ПРОВЕРЕНО: пользовательское требование]
- **Варианты:** срез по направлению взгляда; фиксированная мировая высота; текущая высота шлема ±3 cm. [ПРОВЕРЕНО: перечисленные варианты]
- **Решение:** горизонтальная проекция по yaw шлема; вертикальный фильтр `abs(point.y-headset.y) <= 0.03 m`; общая толщина полосы 0.06 m. [ПРОВЕРЕНО: `LiveScanMinimap.cs`]
- **Обоснование:** pitch взгляда не должен наклонять срез; текущая высота головы позволяет карте следовать при приседании. [ПРОВЕРЕНО: user requirement/design]
- **Последствия:** разреженная выборка может оставить карту пустой; добавлен sample budget 768 и источник точек из финального меша. [ПРОВЕРЕНО: source]; плотность на устройстве требует проверки.

## ADR-007 · Смешанный режим как третий post-scan view

- **Контекст:** пользователь требует одновременно видеть реальный passthrough и scan mesh. [ПРОВЕРЕНО: user request]
- **Варианты:** отдельные camera-only/scan-only режимы; mesh поверх passthrough; opaque scan background. [ПРОВЕРЕНО: рассматриваемые решения]
- **Решение:** цикл passthrough-only → mixed (passthrough+mesh) → scan-only. [ПРОВЕРЕНО: source 0.5.11+]
- **Обоснование:** сравнение восстановленной геометрии с физической комнатой. [ПРЕДПОЛОЖЕНИЕ]
- **Последствия:** порядок композитинга, окклюзия и depth должны быть проверены на шлеме; в текущем source выявлена рассинхронизация начального состояния и внутреннего cycle index. [ПРОВЕРЕНО: static audit]; [ТРЕБУЕТ ПРОВЕРКИ: headset]

## ADR-008 · Релокация через capture matrix пространственного якоря

- **Контекст:** после выхода за границу tracking area или сна скан наблюдался повёрнутым относительно физической комнаты. [ПРОВЕРЕНО: user report]
- **Варианты:** поправка по текущему yaw головы; MRUK room frame; relocation через spatial anchor matrix; требовать повторное сканирование после tracking reset. [ПРОВЕРЕНО: варианты]
- **Решение:** `R=A_now * inverse(A_capture)`, захватить matrix при старте скана, применить translation/rotation к visual root. [ПРОВЕРЕНО: `ArescopeFrame.cs`]
- **Обоснование:** anchor frame предпочтительнее предположения о стабильности Unity world origin. [ПРЕДПОЛОЖЕНИЕ]
- **Последствия:** корректность зависит от совместимости координат меша и матрицы, а также от сохранения/релокализации якоря; на устройстве не доказано. [ТРЕБУЕТ ПРОВЕРКИ]

## ADR-009 · Раздельные producer/viewer bearer roles

- **Контекст:** устройство пишет frames/mesh/logs; browser читает sessions/exports. [ПРОВЕРЕНО]
- **Варианты:** единый read/write токен; отдельные producer/viewer tokens; только cookie auth. [ПРЕДПОЛОЖЕНИЕ: варианты]
- **Решение:** разделить producer и viewer роли, передавать Bearer header для HTTP API. [ПРОВЕРЕНО: LAB source]
- **Обоснование:** ограничить browser credential чтением, а device token — ingest действиями. [ПРЕДПОЛОЖЕНИЕ]
- **Последствия:** producer token, встроенный в APK, извлекаем; ротация/revocation и ограничение на устройство остаются операционными требованиями. [ПРОВЕРЕНО: extractable resource]; [ТРЕБУЕТ ПРОВЕРКИ: enforcement]
